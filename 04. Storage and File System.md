# 04. Storage and File System

## 1. Add and mount a second virtual disk

Linux names disks `sda`, `sdb` and so on, with partitions numbered `sda1`, `sdb1`. Knowing exactly which disk I am working on matters, because pointing `fdisk` at the wrong disk can damage it.

I checked the existing storage with `df -h`; the main disk was about 30 GB. To avoid wasting the 256 GB host disk I added a smaller 10 GB disk: with the VM shut down, **VM, Settings, Add, Hard Disk**, then powered it on again.

| Step | Command | Result |
| --- | --- | --- |
| Confirm the disk | `lsblk` | `sda` (original) and `sdb` (new) |
| Partition | `sudo fdisk /dev/sdb` | One partition, `/dev/sdb1` |
| Format | `sudo mkfs.ext4 /dev/sdb1` | ext4 file system |
| Create a mount point | `sudo mkdir /mnt/data` | Empty directory |
| Mount temporarily | `sudo mount /dev/sdb1 /mnt/data` | Visible in `df -h` |
| Find the UUID | `sudo blkid /dev/sdb1` | Stable identifier |
| Make it permanent | Add a line to `/etc/fstab` | Mounted at boot |
| Test | `sudo reboot`, then `df -h` | Still mounted |

The `fstab` entry (see `configs/fstab-entry.txt`):

```
UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /mnt/data ext4 defaults 0 2
```

A UUID identifies the file system more reliably than a device name that could change. A temporary mount disappears after a reboot, which is why the `fstab` line is needed. The placeholder UUID above is not the real one.

I learned to never rush disk commands: a typo in a text file is annoying, but pointing a partitioning tool at the wrong disk can destroy data.

## 2. The Linux file system hierarchy

Everything hangs from `/`. Directories I use most:

| Directory | Contents |
| --- | --- |
| `/etc` | System and service configuration files |
| `/home` | Users’ home directories |
| `/var` | Variable data such as logs and web content |
| `/usr` | Installed programs and libraries |
| `/tmp` | Temporary files |
| `/dev` | Device files such as `/dev/sda` |
| `/mnt` | Conventional place for mounting extra file systems |

Knowing where things live speeds up troubleshooting: configuration in `/etc`, logs in `/var`, user data in `/home`.

## 3. File management

| Task | Command |
| --- | --- |
| Where am I | `pwd` |
| Change directory | `cd /home/klint`, `cd ..` |
| List | `ls`, `ls -l` |
| Create a file or folder | `touch myfile.txt`, `mkdir myfolder`, `mkdir -p parent/child/newfolder` |
| View a file | `cat`, `head`, `tail`, `tail -f app.log` (follow a log live) |
| Move or rename | `mv myfile.txt myfolder/`, `mv oldname.txt newname.txt` |
| Copy | `cp myfile.txt /home/klint/backup/`, `cp -r parent/ backup/` |
| Delete | `rm myfile.txt`, `rm -r myfolder` (permanent, no recycle bin) |
| Find | `sudo find / -name findme.txt` |

## 4. Permissions and ownership

`ls -l` shows the permission string, for example `rwxr-xr--`: three sets for owner, group and others, each made of read (`r`), write (`w`) and execute (`x`). The numeric form adds values `r=4`, `w=2`, `x=1`, so `rwxr-xr--` is `754`.

| Task | Command |
| --- | --- |
| Change permissions | `chmod 774 hello.py`, `chmod -R 750 parent/` |
| Change owner | `sudo chown root hello.py` |
| Change owner and group | `sudo chown root:klint hello.py` |
| Protect a sensitive file | `chmod 600 sensitive-file` |

My rules:

- Give only the access that is needed (least privilege).
- Avoid `777`: it solves the immediate problem while creating a much bigger security problem.
- Restrict sensitive files such as SSH material and configuration.
- Grant execute permission only to files that should run.
