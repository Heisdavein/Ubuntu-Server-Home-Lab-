## 1. First Python script

`scripts/hello.py`:

```python
#!/usr/bin/env python3
print("Hello, world!")
print("This is my first Python script running on Ubuntu Server.")
```

The first line is the **shebang**, which tells Linux which interpreter to use. Run it two ways:

```bash
python3 hello.py        # through the interpreter
chmod +x hello.py       # make it executable
./hello.py              # run it as a program
```

I checked the result with `ls -l`, where the `x` permission appears after `chmod +x`.

## 2. First Bash script

`scripts/welcome.sh`:

```bash
#!/bin/bash
echo "Welcome to my Ubuntu Server!"
date
uptime
```

```bash
nano welcome.sh
chmod +x welcome.sh
./welcome.sh
```

It prints a message, the current date and the system uptime. A script reduces mistakes and makes a routine repeatable.

## 3. Bash cheat sheet

My notes cover script structure, variables (used as `echo "Hello, $name"`), user input, conditionals, loops, functions, arithmetic, arrays (`${fruits[1]}`, `${fruits[@]}`), file and directory checks, command substitution (`$date_today`), error handling (`command || echo "Command failed"`), `case` statements, logging with `>>`, and script permissions (`chmod 700` for private scripts). ## 4. Scheduling with cron

Cron runs tasks automatically. The cron daemon checks scheduled jobs every minute.

| Command | Purpose |
| --- | --- |
| `crontab -e` | Edit my personal schedule |
| `crontab -l` | List my scheduled jobs |
| `crontab -r` | Remove my entire crontab (use with care) |

System-wide locations: `/etc/crontab`, `/etc/cron.d/`, and `/etc/cron.daily/`, `/etc/cron.weekly/`, `/etc/cron.monthly/`.

Time syntax is five fields followed by the command:

```
* * * * * command-to-run
| | | | |
| | | | +-- Day of week (0-7)
| | | +---- Month (1-12)
| | +------ Day of month (1-31)
| +-------- Hour (0-23)
+---------- Minute (0-59)
```

| Schedule | Meaning |
| --- | --- |
| `0 2 * * * /usr/bin/backup.sh` | 02:00 every day |
| `*/15 * * * * /usr/bin/check_status.sh` | Every 15 minutes |
| `30 1 * * 1 /usr/bin/restart-web.sh` | 01:30 every Monday |
| `0 0 1 * * /usr/bin/archive.sh` | Midnight on the first of each month |

### My scheduled backup

```bash
chmod +x /home/klint/backup.sh
crontab -e
```

```
0 3 * * * /home/klint/backup.sh >> /var/log/backup.log 2>&1
```

It runs the script at 03:00 every day and appends both normal output and errors (`2>&1`) to `/var/log/backup.log`, so there is a record to read if something fails. The contents of `backup.sh` are not recorded here. Entry also in `configs/crontab-entry.txt`.

Cron practices I noted: use full paths, make scripts executable, log output, and remember that user crontabs are stored under `/var/spool/cron/crontabs/` and should be edited with `crontab -e`, not by hand.
