# 03. System and User Administration

## 1. Updating the system

Software has bugs and vulnerabilities, and fixes arrive as updates. A server that is not updated can run software with known problems. `apt update` and `apt upgrade` do different jobs:

```bash
sudo apt update        # refresh the list of available versions
sudo apt upgrade       # install newer versions of installed packages
sudo apt autoremove    # remove automatically installed packages no longer needed
sudo apt clean         # remove cached package files
```

`apt update` finds out what is available; `apt upgrade` installs it. I run them together in that order, and finish with the cleanup commands.


## 2. Users

Linux has regular users and system users, which services use as their own identities. Listing local accounts shows many I did not create:

```bash
cut -d: -f1 /etc/passwd
```

| Task | Command |
| --- | --- |
| Create a user | `sudo adduser devuser` |
| Check the home directory | `ls -l /home` |
| Switch user | `su - devuser`, check with `whoami`, leave with `exit` |
| Give admin rights | `sudo usermod -aG sudo devuser` |
| Delete a user | `sudo deluser devuser` |
| Delete a user and the home directory | `sudo deluser --remove-home devuser` |

Two cautions I wrote down. Membership of the `sudo` group gives administrative power and should be given carefully, and `-aG` must keep the `-a` so existing groups are not replaced. `--remove-home` permanently deletes the user’s files, so back up or check first.

## 3. Groups

Groups let permissions be given to several users at once.

| Task | Command |
| --- | --- |
| Show a user’s groups | `groups devuser` |
| Create a group | `sudo addgroup developers` |
| Add a user to a group | `sudo usermod -aG developers devuser` |
| Remove a user from a group | `sudo gpasswd -d devuser developers` |
| List groups | `getent group`, `getent group developers`, `cat /etc/group` |

Using `usermod -G` without `-a` replaces the user’s supplementary groups, and `-g` changes the primary group. System groups should not be changed carelessly.

## 4. Root and sudo

Root has unrestricted control. Ubuntu discourages logging in directly as root. Instead an authorised user runs individual commands with `sudo`, which limits the time spent with full privileges and reduces the chance of a damaging mistake.

My rules for `sudo`:

- Stay a normal user and elevate one command at a time.
- Do not stay in a root shell (`sudo su`) longer than needed.
- Understand a command before putting `sudo` in front of it. `sudo` does not make a command safe, it gives it more power (`sudo rm -rf /` is the example of what not to do).
- Add users to the `sudo` group only when they need it.

## 5. Text editors

| Editor | Notes |
| --- | --- |
| nano | Beginner-friendly. Shortcuts shown at the bottom: `Ctrl+W` search, `Ctrl+K` cut, `Ctrl+U` paste, `Ctrl+X` exit then `Y` or `N` to save |
| vim | Powerful, steeper learning curve, modal editing; saving and quitting are separate commands |

I practised both on `/etc/hostname`:

```bash
sudo nano /etc/hostname
sudo vi /etc/hostname
```

nano is the easier choice for quick edits, while vim is present on almost every Linux system and worth learning.
