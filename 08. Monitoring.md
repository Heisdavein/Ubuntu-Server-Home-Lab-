# 08. Monitoring

A server that cannot be observed cannot be managed. I learned the tools for each resource, then configured SNMP so the server can report its own health to a monitoring system.

## 1. CPU and processes

```bash
sudo apt install htop
htop
```

`htop` shows per-core CPU usage, memory, running processes and system information (load, uptime). Sorting by CPU shows which process is using the most. Processes can be handled from the command line:

```bash
ps aux
sudo kill 2451         # ask the process to stop gracefully
sudo kill -9 2451      # force termination, last resort
```

A graceful stop lets a program save its work and close files, so `kill -9` is only for processes that will not respond. The PID `2451` is an example. CPU **usage** is a moment in time, while **load** shows how much work is waiting, so both matter. `htop` only shows the situation while I am looking.

## 2. Services with systemctl

A service is a program running in the background, such as SSH, Apache or Fail2Ban. `systemctl` controls them.

| Task | Command |
| --- | --- |
| Start / stop | `sudo systemctl start apache2`, `sudo systemctl stop apache2` |
| Restart | `sudo systemctl restart apache2` |
| Reload config without a full restart | `sudo systemctl reload apache2` |
| Start at boot / not at boot | `sudo systemctl enable apache2`, `sudo systemctl disable apache2` |
| Check status | `sudo systemctl status apache2` |
| Is it enabled at boot | `sudo systemctl is-enabled apache2` |
| List services | `systemctl list-units --type=service`, add `--all` for inactive ones |
| Reboot / power off | `sudo systemctl reboot`, `sudo systemctl poweroff` |

`status` was the command I used most. One warning I recorded: stopping `ssh` over an SSH session disconnects me, so I do not stop a service I depend on to stay connected.

## 3. Disk space

```bash
df -h                  # free space per file system
sudo du -sh /var/*     # which directories are using space
sudo apt install ncdu
sudo ncdu /            # interactive disk usage browser
sudo apt clean
sudo apt autoremove
```

`df -h` reports size, used, available and the usage percentage; I watch **Use%**. Disks usually fill gradually, through logs, packages and backups, so regular checks catch the trend early. `du` finds where space is going, `ncdu` lets me explore it interactively, and `apt clean` and `apt autoremove` free space safely.

The `df -h` output printed in my notes is an illustrative example, not a capture from this VM.

## 4. Disk I/O

```bash
sudo apt install sysstat
iostat
iostat -xz 5
sudo apt install iotop
sudo iotop
vmstat 3
```

| Tool | Use |
| --- | --- |
| `iostat` | Is the storage device itself busy |
| `iotop` | Which process is causing heavy disk activity |
| `vmstat` | How CPU, memory, swap and disk interact |

## 5. Network interfaces

```bash
ip -s link                       # RX and TX statistics per interface
sudo apt install ifstat && ifstat        # live bandwidth
sudo apt install nload && sudo nload     # graphical traffic view
sudo apt install iftop && sudo iftop -i ens33   # top talkers
sudo ss -tuln                    # listening ports
sudo apt install ethtool && sudo ethtool ens33  # link speed and hardware details
```

Together these answer: how much traffic is going through, who is generating it, which ports are open and what the link supports.

## 6. SNMP for centralised monitoring

The tools above only show information while I am logged in. SNMP lets a monitoring server such as PRTG, Nagios or Zabbix ask the server for CPU, memory, disk, network and uptime. The monitoring system is the SNMP manager and the Ubuntu server runs the SNMP agent (`snmpd`), listening on UDP port 161.

```bash
sudo apt update
sudo apt install snmp snmpd -y
sudo cp /etc/snmp/snmpd.conf /etc/snmp/snmpd.conf.bak
sudo nano /etc/snmp/snmpd.conf
```

`snmp` provides client utilities and `snmpd` is the agent. I backed up the configuration before editing. Settings (`configs/snmpd.conf-changes.txt`):

```
rocommunity mySecureString default -V systemonly
agentAddress udp:192.168.1.149:161
```

- `rocommunity` creates a **read-only** community. I replaced the default `public` with my own string, because a well-known default is guessable. `mySecureString` is a placeholder.
- `V systemonly` limits the view of data.
- `agentAddress` makes the agent listen only on the server’s own address.

```bash
sudo systemctl restart snmpd
sudo systemctl enable snmpd
sudo ufw allow from 192.168.1.0/24 to any port 161 proto udp
snmpwalk -v2c -c mySecureString localhost
```

The firewall rule allows SNMP only from my local network. `snmpwalk` is the test: if the agent responds it returns management information such as system description, name and uptime. The command is documented, but its output is not recorded in my notes.

SNMP v2c sends the community string in clear text, so it should only be used on trusted networks.
