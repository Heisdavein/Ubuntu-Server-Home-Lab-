# 01. VM and Installation

Covers downloading and verifying Ubuntu Server, creating a VM sized for an 8 GB host, and installing the operating system.

## 1. Download and verify the ISO

I chose **Ubuntu Server 24.04.2 LTS**, a long-term-support release suited to a lab I plan to keep using. I downloaded the Live Server ISO from the official Ubuntu website.

An ISO is a complete image of an installation disc. Ubuntu publishes a SHA256 checksum for it, a fingerprint that changes if even a small part of the file changes. Checking it proves the file downloaded correctly and matches the published version.

On Windows 11, in PowerShell from the folder containing the ISO:

```powershell
Get-FileHash .\ubuntu-24.04.2-live-server-amd64.iso -Algorithm SHA256
```

The hash matched the value published by Ubuntu.

## 2. Create the virtual machine

I asked how much hardware I could safely give the VM while keeping the host usable, rather than how much the VM could have.

1. VMware Workstation Pro, **Create a New Virtual Machine**, **Typical**.
2. Choose **I will install the operating system later**, so the virtual hardware is created first.
3. Guest OS **Linux**, version **Ubuntu 64-bit**.
4. Name: `ubuntu-server`, stored on the SSD for faster disk operations.
5. Virtual disk: **30 GB**. Allocating 60 GB because another tutorial did would waste a 256 GB SSD that also holds Windows, VMware, other VMs and ISOs.
6. Select **Customize Hardware** before finishing.

| Setting | Value | Reason |
| --- | --- | --- |
| Memory | 2048 MB | Enough for Apache, Samba and monitoring tools, while leaving memory for Windows |
| Processors | 1 processor, 2 cores | About half the host’s cores, leaving capacity for Windows and other tools |
| Virtualize Intel VT-x/EPT | Enabled | Hardware-assisted virtualization |
| CD/DVD | Ubuntu ISO, **Connect at power on** | VM boots straight into the installer |
| Network adapter | **Bridged** | The VM is a separate device on the home network with its own IP |

More memory or CPU is not automatically better: giving the VM too much starves the host and slows both. For this lab:

```
Host: 4 cores, 8 GB RAM, 256 GB SSD
  -> Ubuntu VM: 2 cores, 2 GB RAM, 30 GB disk
  -> Remaining: Windows 11, VMware and other applications
```

## 3. Install Ubuntu Server

I powered on the VM. The server installer is text-based, which made me pay attention to each choice.

| Screen | Choice | Reason |
| --- | --- | --- |
| Language | English | Documentation, examples and error messages are in English |
| Keyboard | Checked against my physical keyboard | A wrong layout changes `@`, quotes and password symbols |
| Network | DHCP from the router (temporary) | Gets the installer online; a static IP comes later with Netplan |
| Proxy | Blank | No proxy on my home network |
| Mirror | Default | Ubuntu picks a suitable mirror |
| Storage | **Use an entire disk**, default **LVM** layout | Simplest sensible layout; LVM makes later resizing easier |
| Profile | Name, server name, username, strong password | Normal admin account, used with `sudo` instead of root |
| SSH | **Install OpenSSH server** | Remote administration from the first boot |
| Featured snaps | None selected | I install services manually so I learn each step |

If OpenSSH is forgotten it can be installed later with `sudo apt update` and `sudo apt install openssh-server`.

When the installer finished I selected **Reboot Now**. The VM booted from the disk to a plain `ubuntu-server login:` prompt. There is no desktop: Ubuntu Server is headless by design, which saves RAM and CPU, speeds up boot and reduces the attack surface.
