# 05. File Sharing and Services

## 1. WinSCP

My main computer runs Windows, so I needed a way to move files to the server. **WinSCP** is a graphical client that uses SFTP or SCP over SSH, so transfers are encrypted.

| Field | Value |
| --- | --- |
| File protocol | SFTP |
| Host name | The server’s static IP |
| Port | 22 |
| Username and password | My Ubuntu account |

The first connection showed a host-key warning, which I accepted for my own VM. WinSCP shows my Windows computer on the left and the Ubuntu server on the right, so a transfer is drag and drop.

I tested by uploading a small file to my home directory and checking it with `ls -l` over PuTTY, then downloading a file back to Windows. Both directions worked. Linux permissions still apply: transferring a file into a directory only root can write to does not give me the right to edit it.

## 2. Samba share

Samba lets Ubuntu act as a file server that Windows can reach over SMB. WinSCP is for transferring files; Samba makes a folder on the server available as a network share.

```bash
sudo apt install samba
sudo mkdir /mnt/data/share
sudo chown nobody:nogroup /mnt/data/share
sudo chmod 0775 /mnt/data/share
sudo nano /etc/samba/smb.conf
```

Added to `smb.conf` (see `configs/smb.conf-share.txt`):

```
[share]
path= /mnt/data/share
browsable=yes
read only=no
guest ok=yes
```

```bash
sudo systemctl restart smbd
sudo systemctl status smbd
```

The share lives on the second virtual disk. I connected from Windows File Explorer and tested both ways: a file created from Windows appeared in `ls -l /mnt/data/share` on Ubuntu, and a file created on Ubuntu appeared in Explorer. Testing both directions shows that permissions, authentication and access all work, not just that the folder is visible.

**Security note.** `guest ok = yes` meant Windows needed no username or password. That is acceptable on a private, isolated lab network but it lets anyone who can reach the share use it. In production I would use authenticated users, controlled permissions, network restrictions and firewall rules. Something working is not the same as something secure.

## 3. Package management with APT

| Task | Command |
| --- | --- |
| Refresh package lists | `sudo apt update` |
| Install | `sudo apt install htop` |
| Remove | `sudo apt remove htop` |
| Search | `apt search nginx`, `apt search web server` |
| List installed | `apt list --installed` |
| Install a local `.deb` | `sudo dpkg -i package.deb` |
| Install a snap | `sudo snap install <name>` |

APT works with repositories and resolves dependencies. `dpkg` is the lower-level tool for individual `.deb` files, and snap is a separate packaging system. Installing from the repositories beats downloading programs from random websites: software is tracked, updated and removable.

## 4. Apache2 web server

```bash
sudo apt update
sudo apt install apache2 -y
sudo systemctl status apache2
```

Apache2 serves web pages over HTTP on port 80. The web root is `/var/www/html`. I replaced the default page with my own:

```bash
sudo rm /var/www/html/index.html
sudo nano /var/www/html/index.html
sudo systemctl restart apache2
```

The page content is in `scripts/index.html`. From a Windows browser I opened `http://<server-ip>` and the page displayed “Hello from my Ubuntu Server home lab!”

A successful page load shows several things at once: the VM is running, the network path works, Ubuntu has a usable address, Apache is running and listening, the HTTP connection works, and the document root and HTML are valid.

```bash
sudo apt install python3
sudo apt install python3-pip -y

python3
```

I checked whether Python was already installed before installing it, installed pip, and tested the interpreter by running `print("hello from Python on my Ubuntu server")` and leaving with `exit()`. I also looked at installing packages such as `flask` and `requests` with `pip3 install`.
